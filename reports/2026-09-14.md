## Термины и технологии

| Термин | Объяснение |
|---|---|
| `fallback` у `<Suspense>`, рендерящийся СЕРВЕРОМ | `<Suspense>` в React обычно показывает `fallback`, пока асинхронный контент грузится, и его принято считать «временной заглушкой для клиента». Но на статической странице (как `/marketplace`) `fallback` — это то, что попадает в HTML, который отдаёт сервер, если содержимое `<Suspense>` не может быть отрисовано на сервере вообще (здесь — потому что `CategoryFilter`/`MarketplaceCatalog` читают адрес через `useSearchParams`, а это работает только в браузере). До 07.09 `fallback` не было вовсе, и в этом месте HTML стоял пустой узел нулевой высоты. Положив туда настоящую разметку (`MarketplaceShowcase`, `CategoryFilterStatic`), эту пустоту убрали — приём, специфичный для сочетания статической генерации и клиентских компонентов, а не общий факт про `Suspense`. |
| Один отрисовщик, два вызывающих (server и client) | `MarketplaceShowcase.tsx` не помечен `"use client"`, поэтому одна и та же функция-компонент может быть вызвана и с сервера (как `fallback` в `marketplace/page.tsx`, при сборке статической страницы), и с клиента (изнутри `MarketplaceCatalog.tsx`, который сам клиентский). Раз в файле нет серверных API (запросов к БД, `cookies()` и т.п.), а есть только JSX над уже переданными данными — он одинаково валиден в обеих средах. Приём убирает саму возможность разъехаться: разметка ряда подборок описана один раз, а не в двух похожих файлах. |
| Ноль высоты у нерендеренного поддерева (нулевой CLS-эффект пустоты) | Когда React/Next не рисует какой-то узел на сервере (нет `fallback`, компонент условно скрыт и т.п.), в потоке документа на его месте не остаётся ничего — ни `<div>`, ни зарезервированного места, высота ровно 0px. Браузер, догрузив JavaScript и вставив туда реальный контент, физически раздвигает всё, что стояло ниже — это и есть layout shift, который измеряет CLS. Урок недели: невидимый узел — не то же самое, что узел с `height: 0` намеренно; первое ломает вёрстку, второе иногда осознанный приём. |
| Крawlable ссылка vs интерактивная кнопка без обработчика | Поисковый робот и человек с отключённым JavaScript не выполняют `onClick`, поэтому единственный способ «нажать» на что-то для них — настоящий `<a href="...">`, по которому браузер (или краулер) переходит без единой строчки JS. Кнопка (`<button>`) без `href` и без работающего обработчика — тупик для обоих. Ровно поэтому пилюли категорий в `CategoryFilterStatic.tsx` сделаны ссылками `next/link`, а не кнопками: до 07.09 в HTML не было вообще ни одной ссылки на категорию, значит краулер не мог найти путь в каталог иначе как через главную страницу целиком. |
| `aria-hidden` | Атрибут, которым помечают элемент как «не существующий» для программ чтения с экрана — они его полностью пропускают, даже если он виден зрячему пользователю. В `CategoryFilterStatic.tsx` так помечены декоративная заглушка поля поиска и кнопка «Filters»: оба — временные фигуры, которые исчезнут в момент гидратации, и объявлять незрячему посетителю поле, в которое нельзя набрать текст, было бы хуже, чем не объявлять его вовсе. |
| Приватная функция, общая для двух публичных хуков | `useEscapeStack` в `useDismiss.ts` не экспортируется из файла — её видят только `useDismiss` и `useEscapeLayer`, объявленные в том же модуле. Это обычный приём инкапсуляции (как приватный метод класса в ООП, к которому апеллирует `docs/RULES.md` в разделе про калибровку объяснений): общая логика существует один раз, а наружу торчат только два осмысленных публичных интерфейса — «выпадашка с кликом мимо» и «просто слой в очереди Escape». |
| Медиана из трёх прогонов и «прогрев» после рестарта сервера | Метод измерения производительности, устойчивый к случайным выбросам: вместо одного замера Lighthouse делают три и берут средний по порядку (медиану), а не среднее арифметическое — единственный аномальный результат (например, первый запрос после перезапуска сервера, когда кеши ещё холодные) не тянет общий вывод в сторону. В `docs/CHANGELOG.md` за 07.09 описан конкретный случай: первый прогон после `next start` дал 74 балла и LCP 6.0с против медианных 80 и 4.6-5.2с — «доказать» правкой можно что угодно, если мерить один раз. |
| Архивация выполненной документации (`docs/archive/`) | Практика, при которой документ не удаляется и не правится, а перекладывается в отдельную папку с README, объясняющим, чем он был и почему больше не действует как план. Отличие от простого удаления — сохранение объяснения решений (в `docs/archive/HANDOFF-claude-code.md` лежат решения, которые всё ещё цитируются из `CLAUDE.md`), отличие от оставления на месте — явный сигнал «это история, а не текущая работа», которого не хватало, пока файл лежал в общей куче с активными планами. |
| Комментарий, переживший число, которое объяснял | Конкретная форма устаревания документации: значение (тут — 14 дней вместо 30) меняется в одном источнике правды (константа `USERNAME_COOLDOWN_DAYS`), код, который его показывает пользователю, обновляется автоматически, а текстовые комментарии рядом — нет, потому что их никто не обязан перечитывать при правке миграции. `docs/RULES.md` называет это по имени как отдельный урок: комментарий с устаревшим числом хуже отсутствующего комментария, потому что внушает уверенность, которой факт не подтверждает. |
| `priorityFirst` как проп, управляющий чужим пропом ниже по дереву | `MarketplaceShowcaseRow` получает булев `priorityFirst` и сам решает, какому из своих дочерних `ProductCard` передать `priority={true}` (только элементу с индексом 0), а остальным — `false`. Это обычный паттерн «проп управляет условной передачей другого пропа глубже по дереву компонентов» — знание о том, что LCP-элемент есть только один, инкапсулировано на уровне ряда, а не рассыпано по вызывающему коду, которому пришлось бы самому знать индекс. |

**Итог по разделам:** дизайн-чек и проверка структуры не нашли ни одного 🔴
и ни одного 🟡 — оба содержательных коммита периода целиком закрывают долги
(находки прошлого отчёта) и закрывают их именно так, как отчёт предлагал.
Единственное, что стоит внимания владельца, — не в коде: семь дней без
единого коммита и непроверенная на проде правка витрины, о чём сказано в
«Главном» выше.
