## Термины и технологии

| Термин | Объяснение |
|---|---|
| TOTP (Time-based One-Time Password) и `aal2` | TOTP — шестизначный код, который приложение-аутентификатор (Google Authenticator, 1Password) считает из общего с сервером секрета и который меняется раз в 30 секунд; на этом секрете не нужен поход в сеть, чтобы его проверить. `aal2` (Authenticator Assurance Level 2) — отметка Supabase Auth у СЕССИИ (не у аккаунта): «эта сессия подтвердила код, а не только пароль». `TwoStepSetup.tsx` заводит фактор и секрет, `getAdminGate()` (`lib/admin.ts`) на каждом запросе к `/admin/*` спрашивает именно уровень текущей сессии — украденный пароль открывает новую сессию только до `aal1`. |
| `light-dark()` (CSS-функция) | Встроенная в современные браузеры функция, которая выбирает одно из двух значений по текущему `color-scheme` страницы — без написания отдельного `dark:`-правила. `nameColorStyle()` в `name-colors.ts` пишет `color: light-dark(#значение-для-светлой, #значение-для-тёмной)` прямо в инлайновый `style`, потому что `color-scheme` на сайте всегда совпадает с темой (`ThemeProvider.tsx` ставит класс `.dark`, а не системную настройку), и браузер сам знает, какое из двух значений показать. |
| CSRF (Cross-Site Request Forgery) и заголовок `Origin` | Атака, при которой чужая страница в браузере жертвы тихо отправляет запрос на наш сайт, используя уже залогиненную cookie жертвы — браузер прикладывает cookie автоматически, не спрашивая, с какой страницы пришёл запрос. Заголовок `Origin` в запросе называет домен, с которого запрос реально отправлен; `proxy.ts` теперь отказывает (403) записи в `/api/*`, если этот домен — не наш. Запросы без `Origin` (Stripe, Discord-бот) проходят отдельно — у них есть собственная криптографическая подпись. |
| `Sec-Fetch-Dest` | Заголовок, который сам браузер добавляет к запросу и честно называет, ЧЕМ на странице этот запрос был вызван — переходом по ссылке, тегом `<img>`, скриптом и так далее; подделать его так, как подделывают `Referer`, заметно труднее. `/api/download` теперь смотрит на это значение и отказывается писать «карту скачали» в журнал, если запрос пришёл не как настоящий переход — иначе `<img src="/api/download?...">` на чужой странице заставлял бы браузер каждого зрителя тихо «скачивать» карту. |
| `search_path` (hijacking через схему) | Список схем Postgres, в которых функция ищет таблицу или другую функцию, названную без явной схемы (`public.foo`, а не просто `foo`). Если у функции `search_path` не задан явно, используется тот, что у ВЫЗЫВАЮЩЕГО — а он может временно подставить свою схему с объектом того же имени и подменить, какой код реально выполнится. Миграция `20261112130000_function_hygiene` проставляет `set search_path = public` семи функциям, у которых он отсутствовал; дырой это не было (все семь работают с правами вызывающего, не с чужими), но Supabase помечает такое предупреждением, и список предупреждений теперь пуст. |
| Политика RLS «по свойству, а не по имени» | Снятие политики безопасности строки (RLS) командой `drop policy if exists "имя"` ничего не ломает и ничего не делает, если политику на самом деле назвали иначе — ошибка молчит, дверь остаётся открытой. Правильный приём — цикл по `pg_policies` с условием «все политики ЧТЕНИЯ у этой таблицы», а не конкретное имя. Миграция `20261112140000_project_drafts` делает ровно так (`do $$ ... loop ... end $$`), прежде чем завести новую политику «только опубликованные» — применение урока, записанного в `docs/INVARIANTS.md`, п. 9, в тот же день, когда он понадобился снова. |
| WCAG-контраст: порог 3.0 против 4.5 | Правило доступности (Web Content Accessibility Guidelines) задаёт минимальное отношение яркости текста к фону — отдельно для КРУПНОГО текста (порог 3.0, например заголовок профиля) и для ОБЫЧНОГО, мелкого (порог 4.5, например подпись под комментарием). Цвет, который проходит 3.0, может не проходить 4.5 — именно это случилось с палитрой цвета ника: она была рассчитана только на крупный текст профиля, а 14.11 цвет понадобился и в мелком тексте карточек и навбара, и половина палитры порог 4.5 не взяла без отдельной пары оттенков. |
| Минимальная сумма платежа Stripe | Stripe физически отказывается создавать платёжную сессию меньше определённой суммы в валюте (для евро — €0.50) — не ограничение нашего кода, а правило платёжной системы. `PRICE_MIN_PAID_CENTS` в `map-submission.ts` отбивает такую цену ещё на сохранении карты, чтобы автор не узнал о проблеме только в момент первой попытки купить. Цена 0 — отдельный случай («бесплатная карта»), она не идёт через Stripe вовсе. |
| Перетаскивание через `Reorder` (библиотека Motion) | Готовый компонент библиотеки Motion, который рисует список, где элементы можно менять местами жестом, без ручной работы с `pointermove`/`pointerup`. `AdminPortfolioList.tsx` использует `dragListener={false}` + `dragControls`, чтобы тащить строку можно было только за выделенную «ручку» (шесть точек), а не весь ряд целиком — иначе любой клик по ссылке «Edit» внутри строки начинал бы перетаскивание вместо перехода. |
| Cherry-pick против merge (git) | `git merge` переносит ВСЮ историю одной ветки в другую; `git cherry-pick <хеш>` переносит ОДИН конкретный коммит, создавая для него новый хеш на целевой ветке — удобно, когда готова только часть работы в `dev`, а остальное (как весь этот аудит) мёржить рано. В этом периоде так в `master` уехали четыре коммита про портфолио и вики, пока девять партий аудита безопасности остались ждать в `dev` — именно это объясняет разницу в 32 коммита между ветками, разобранную в шапке отчёта. |
| Discriminated union-подобный «гейт» (`getAdminGate`) | Функция возвращает не булево «пустить/не пустить», а объект с полем `status` из трёх значений (`"ok"` / `"needs-code"` / остальное) — и дальше код веткуется по этому полю (`layout.tsx`: `redirect` на `needs-code`, `notFound()` на прочее, иначе достаёт `gate.admin`). Вместо пяти отдельных булевых флагов («вошёл?», «админ?», «включён 2FA?», «ввёл код?») — один тип с ясным списком состояний, тот же приём, что `ScanOutcome` в `scanner-client.ts` из прошлого периода. |
