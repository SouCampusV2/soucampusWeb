🟡 **`src/lib/useDismiss.ts` — `useDismiss` (56-109) и `useEscapeLayer` (121-145) держат почти одинаковый блок логики очереди Escape**: обе функции заводят `close = () => latest.current()`, пушат его в общий `escapeStack`, слушают `keydown`, сверяют `escapeStack[escapeStack.length-1] === close` и убирают себя по значению (`lastIndexOf`/`splice`) при размонтировании. Около 10 строк повторены дословно в одном и том же файле, написанном в один день (`f73a5cf`, 06.09) — то есть не «разъехавшиеся со временем копии», а копипаст в момент письма. Кандидат на вынос:
```tsx
// useDismiss.ts — общая часть, вынесенная в приватный хук:
function useEscapeStack(onEscape: () => void, enabled: boolean) {
  const latest = useRef(onEscape);
  useEffect(() => { latest.current = onEscape; });

  useEffect(() => {
    if (!enabled) return;
    const close = () => latest.current();
    escapeStack.push(close);
    function onKeyDown(event: KeyboardEvent) {
      if (event.key === "Escape" && escapeStack[escapeStack.length - 1] === close) close();
    }
    document.addEventListener("keydown", onKeyDown);
    return () => {
      document.removeEventListener("keydown", onKeyDown);
      const at = escapeStack.lastIndexOf(close);
      if (at !== -1) escapeStack.splice(at, 1);
    };
  }, [enabled]);
}
// useEscapeLayer становится однострочной обёрткой над useEscapeStack;
// useDismiss вызывает её же и отдельно вешает pointerdown.
```
Невысокий приоритет — файл маленький (145 строк), обе копии видны в одном экране редактора и вряд ли разъедутся молча так, как это случилось с семью копиями градиента. Но раз в файле уже есть подробный комментарий про историю «пяти копий одного эффекта», стоило заметить шестую и седьмую копию в себе самом.

## Термины и технологии

| Термин | Объяснение |
|---|---|
| Стек событий на уровне модуля (module-level stack) | Массив `escapeStack` в `useDismiss.ts:56` живёт не в React-состоянии, а как обычная переменная модуля — общая для всего дерева компонентов. Каждая открытая выпадашка кладёт в него свою функцию закрытия при монтировании и убирает при размонтировании; клавиша Escape всегда достаётся только последней добавленной. React-контекст здесь не подошёл бы: вопрос «кто сейчас открыт последним» касается всего приложения сразу, и оборачивать в провайдер пришлось бы всё дерево ради одной клавиши. |
| Тест свойства vs тест примеров (property-based vs example-based) | Обычный тест проверяет конкретные случаи («редирект `/shop` работает», «редирект `/creator/upload` работает») — и молчит про случай, который никто не предвидел. `route-rules.test.ts` вместо этого проверяет общее свойство: «ни одно правило `redirects()` не перехватывается более ранним для ЛЮБОГО адреса, который оно ловит» — переберая все пары правил друг против друга. Свойство ловит и уже известные конфликты, и следующий такой же, которого ещё не было. |
| Слепая зона grep (наблюдение из инвентаризации шлюза записи) | Команда `grep "insert\|update\|delete" | grep "\.from("` казалась исчерпывающей проверкой всех записей в базу и нашла 3 из 13 реальных путей. Она физически не видит: вызов, разбитый на несколько строк (`grep` читает по одной строке за раз), запись через `rpc()` (там нет слова `insert`, только имя функции типа `soft_delete_comment`), и загрузку файла в Storage (`storage.from(...).upload(...)` — это тоже запись, просто не в таблицу). Урок шире конкретной команды: инструмент, отвечающий правдоподобным числом, опаснее инструмента, отвечающего нулём — ноль заставляет проверить, три — записывается в план как факт. |
| `role="listbox"` / `role="option"` / `aria-selected` (ARIA) | Набор атрибутов, которыми самодельный выпадающий список объясняет программам чтения с экрана, что он собой представляет — «это список для выбора одного варианта», «это один из вариантов», «этот вариант выбран сейчас». Обычный `<div>` или `<button>` без них не отличим для незрячего пользователя от произвольного текста. `SelectField.tsx` получил их взамен нативного `<select>`, у которого вся эта семантика была встроена браузером бесплатно — это часть цены замены, честно прописанная в комментарии файла. |
| Идемпотентная миграция, меняющая константу (`create or replace function`) | `20260906130000_username_cooldown_14_days.sql` не создаёт новую функцию `guard_username_change`, а переопределяет уже существующую тем же именем (`create or replace function`) — Postgres заменяет тело функции, сохраняя все права и ссылки на неё. Это тот же приём, которым в августе меняли `guard_product_state` при появлении новых переходов: правило живёт в одном месте (триггере), и его пересмотр — это правка функции, а не новая сущность рядом со старой. |
| CLS (Cumulative Layout Shift) | Один из трёх основных показателей Core Web Vitals (наряду с LCP и INP) — сумма того, насколько элементы страницы «прыгают» уже после первой отрисовки. Порог хорошего результата — 0.1; у витрины магазина замер 06.09 показал 0.452. Причина: `CategoryFilter` и каталог — клиентские компоненты, читающие адрес страницы, а `Suspense` вокруг них не имеет `fallback` — то есть сервер сначала не рисует под ними вообще ничего, а когда браузер догружает JavaScript, весь список карт вставляется между уже показанными заголовком и баннером, сдвигая всё, что ниже. |
| `priority` у `next/image` против `loading="lazy"` | Два противоположных намерения для одной и той же картинки. `priority` говорит Next.js загрузить изображение сразу и в первую очередь — для LCP-элемента экрана (`MarketplaceCta.tsx`) это правильно, а без него браузер намеренно откладывает загрузку самой измеряемой картинки. `loading="lazy"` — наоборот, откладывает загрузку до момента, когда элемент вот-вот попадёт в область видимости; добавлен на аватар в `Avatar.tsx`, потому что React сам ставит предзагрузку (`<link rel="preload">`) на каждую отрисованную на сервере картинку, включая крошечный аватар в свёрнутом меню, который browser предзагружает, не показывает и потом жалуется в консоль. |
| `aria-labelledby` вместо `<label for>` | Способ связать подпись поля с самим полем для чтения с экрана, когда поле — не `<input>`/`<select>`, а кнопка (как в новом `SelectField.tsx`). Обычный `<label htmlFor="id">` работает только с полями ввода — клик по подписи ставит на них фокус. У кнопки-триггера своя семантика (`role="button"`, а не текстовое поле), поэтому связь идёт явным `aria-labelledby`, указывающим на `id` текста подписи — для читалки экрана результат тот же: она озвучит подпись при фокусе на кнопке. |
| Route shadowing (правило, перехваченное более ранним) | Next.js проверяет список `redirects()`/`rewrites()` сверху вниз и применяет первое совпавшее правило, не проверяя остальные. Если раннее правило написано широко (например, `/creator/:username` — любой односегментный адрес), оно «затеняет» любое более узкое правило под тем же префиксом, написанное ниже (`/creator/upload`) — второе никогда не сработает, хотя формально существует в файле. Ровно это стоило проекту семи дней в августе; `route-rules.test.ts` теперь проверяет отсутствие такого перехвата для всего файла разом. |
| Table-shaped данные с типизированными блоками текста | Приём, которым `src/lib/wiki.ts` избегает HTML в данных: тело статьи — не строка с разметкой, а массив объектов `{kind: "text"|"steps"|"list"|"note", ...}`. Отрисовщик (`WikiArticleBody.tsx`) сам решает, во что превратить каждый вид блока — нумерованный список для `steps`, маркированный для `list`. Так на сайте не появляется второй путь для разметки в обход общего санитайзера (`sanitize.ts`) — потому что пути через `dangerouslySetInnerHTML` для статей вики просто не существует физически. |
