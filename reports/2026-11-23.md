**1. Прямо сейчас на проде (`master`) стоит зависимость с критической
уязвимостью, и исправление для неё три недели лежит в `dev`, никем не
тронутое.** `npm audit --omit=dev` на чистой переустановке (`npm ci`) из

`soucampus.online` — даёт **4 находки в продакшен-зависимостях: 1
критическая, 2 высоких, 1 средняя**:

  «Unauthenticated Remote Code Execution in Image Optimization API when
  SVG files are used» (`GHSA-2464-fhr4-w9xw`) и «Unauthenticated Remote
  Code Execution in `use cache` functions returning typed arrays»
  (`GHSA-673q-mjm6-r5xr`) — обе без входа, то есть доступны любому
  посетителю сайта.

  namespace-prefix bypass allows `javascript:` URI injection (XSS)»
  (`GHSA-374f-7chj-9948`) — это ровно та библиотека, которая фильтрует

  посетителям.

  после антивируса (`cad19c8`, «images rebuilt with sharp») — то есть
  уязвим ровно тот шаг, который должен быть защитой.

## Термины и технологии

| Термин | Объяснение |
|---|---|
| CVE / GHSA-advisory и `npm audit --omit=dev` | CVE — общий номер известной уязвимости в программе; GHSA — такой же номер в собственной базе GitHub, через которую npm и получает эти данные. `npm audit` сверяет версии пакетов в `package-lock.json` с этой базой. Флаг `--omit=dev` исключает пакеты для разработки (`eslint`, `vitest`) — остаются только те, что реально попадают на сайт в браузер посетителя или на сервер Vercel. Разница между «аудит всего» (18 находок) и «аудит продакшена» (4 находки, 1 критическая) на этой неделе и есть главная находка отчёта. |
| Remote Code Execution (RCE) без входа («unauthenticated») | Самый тяжёлый класс уязвимости: злоумышленнику не нужен пароль или сессия — обычный HTTP-запрос к серверу заставляет его выполнить чужой код. Две из 16 CVE в `next@16.3.6` (на `master`) именно такие — через эндпоинт оптимизации картинок (`/_next/image`) и через внутренний механизм `use cache`. Обе уже закрыты в `next@16.4.4`, который три недели лежит неслитым в `dev`. |
| Внедрение зависимости через параметр по умолчанию | Способ сделать функцию проверяемой без отдельного мок-фреймворка: `checkStoredFile(storage, path, kind, scan = scanWithService)` — четвёртый параметр по умолчанию берёт настоящую функцию сети, но тест может передать свою подделку явным аргументом. Код, который зовёт функцию как обычно (три аргумента), ничего не замечает; тест получает контроль над самым ненадёжным местом (HTTP-запрос к сканеру) без единой библиотеки для подмены. |
| Единый контур (`path`) против отдельных прямоугольников (`<rect>`) в пиксельной SVG | Два способа нарисовать «пиксельную» картинку в векторе. Если каждая клетка — свой `<rect>`, у соседних клеток одного цвета получается общий край, который браузер при масштабировании сглаживает (antialiasing) независимо у каждого прямоугольника — между ними проступает тонкая светлая линия-шов. Если вместо этого все клетки одного цвета объединить в один контур (`path`, как это делает `outline()` в `PixelArt.tsx`), общих внутренних краёв не остаётся — сглаживать можно только внешний контур всей фигуры. Именно эту разницу владелец заметил на цветке `/about` 16.11, а новый компонент `ThemeToggle` в тот же вечер повторил старый способ. |
| Непушенная локальная ветка git | Ветка (`git branch brand`) существует только в истории коммитов на машине, где её создали, пока её не отправили (`git push`) на сервер (`origin`). До этого её не видно ни в GitHub, ни в предпросмотре Vercel (он собирается из того, что лежит на сервере) — и её нельзя открыть для проверки «глазами», даже если локально всё уже готово. На этой неделе редизайн `brand` слился прямо в `dev`, не пройдя через этот шаг, хотя план в `CLAUDE.md` требовал именно отдельного адреса предпросмотра. |
| `self-stretch` (Flexbox) | Свойство CSS-раскладки flex, которое говорит дочернему элементу: «растянись на всю доступную высоту ряда», а не просто «займи высоту своего контента». В навбаре колонка с аккаунтом получила `self-stretch`, чтобы выпадающее меню, расположенное `top-full` (сразу под низом этой колонки), считало своим низом именно нижний край всей пилюли навбара, а не нижний край одной иконки внутри неё — без этого между навбаром и меню оставался зазор. |
| `shrink-0` на изображении внутри flex-колонки | По умолчанию flex-элементы могут сжиматься ниже размера своего содержимого, если ряду/колонке не хватает места. Для картинки это значит, что при разной высоте соседних карточек (из-за разной длины текста) она могла бы невидимо сузиться. `shrink-0` на обёртке картинки запрещает это — сжимается только текстовый блок снизу (`flex-1`), и все карточки ряда получают одну высоту без искажения фотографий. |
| ISO-8601 и сравнение дат строкой | Формат даты вида `2026-11-16T12:40:47+02:00` устроен так, что обычное сравнение строк (`a < b`) даёт тот же результат, что сравнение дат по времени — цифры идут от крупных к мелким (год → месяц → день → час). Поэтому `[...projects].sort((a, b) => (a.createdAt < b.createdAt ? 1 : ...))` в `RecentProjects.tsx` не нуждается в разборе даты в объект `Date` — строка из базы (`created_at`) уже сравнивается правильно. Копия массива (`[...projects]`) обязательна рядом: `.sort()` без неё переставил бы исходный проп, который той же функции нужен ниже неизменным. |
| «Представляющий» цвет против «сигнального» | Разделение, которое в проекте уже существует для `NAME_COLORS` (цвет ника — украшение человека, а не сообщение сайта) и для красок знаков (цветок/веер — цвета дерева/краски игры). На этой неделе тот же принцип понадобился третий раз — для жёлтого солнца и серо-голубой луны в переключателе темы: это цвет самого предмета, а не языка интерфейса (orange/lime/blue), и поэтому не нарушает правило трёх акцентов, хотя формально выходит за палитру. |
