## Термины и технологии

| Термин | Объяснение |
|---|---|
| `git revert` | Команда, которая создаёт НОВЫЙ коммит, отменяющий изменения другого коммита, — в отличие от `git reset`, история не переписывается и ничего не теряется. Коммит `25cc254` этого периода — ровно такой: `git revert e15fd8a` вернул код к состоянию до мёржа, но сам мёрж остался в истории как факт, а не был стёрт. На опубликованной ветке (`master` уже отдан автодеплою) это единственный безопасный способ отменить решение — `reset --hard` + принудительный пуш сломал бы чужие клоны и уже прошедший деплой. |
| Content-Security-Policy, `script-src` | Заголовок, который браузер читает и решает, с каких адресов разрешено подгружать код на странице; всё остальное браузер молча блокирует. Добавление Speed Insights не требовало новой строки в списке — у него тот же хост (`va.vercel-scripts.com`), что уже разрешён для Vercel Analytics (`next.config.ts`), поменялся только комментарий, объясняющий, зачем строка там стоит. |
| Диалоги браузера (`confirm()`/`alert()`) и их заглушка | Браузер показывает собственное окно `confirm`/`alert` без участия сайта — и даёт человеку кнопку «больше не спрашивать для этой страницы». После такого выбора `confirm()` молча возвращает `false` навсегда, без ошибки и без следа. Это ровно причина, по которой в проекте есть свой `ConfirmDialog.tsx` (HTML-разметка, которую сайт полностью контролирует) — находка этого отчёта (`PortfolioForm.tsx`) обходит это правило, уже дважды выученное ценой сломанных без объяснения кнопок (23.08 и 25.08). |
| Представление (view) и его пересоздание `drop` + `create` | `public_profiles` — не таблица, а представление («вид» на реальную таблицу `profiles` с ограниченным набором колонок). Новую колонку (`banner_url`) нельзя добавить в середину списка через `create or replace view` — Postgres требует точного совпадения порядка существующих колонок; миграция `20261025130000_profile_banner.sql` поэтому делает `drop view` + `create view` заново и обязана следом вручную вернуть права (`grant select`), которые `drop` снимает вместе с представлением. |
| Фоллбэк-запрос на случай непрогнанной миграции | Паттерн: сначала запросить данные с новыми колонками, и если PostgREST ответит ошибкой «колонки нет» — повторить запрос без них. Используется в `creators.ts`/`profiles.ts` этого периода для `banner_url`/`created_at`: пока миграция не прогнана на одном из окружений (сначала preview, потом прод — правило проекта), код там не падает целиком, а тихо показывает профиль без баннера. Защищает именно от того разрыва «миграция → деплой», из-за которого проект уже один раз терял день (`docs/RULES.md` → «Миграции»). |
| `on conflict (id) do update` при создании бакета Storage | Вставка настроек бакета (`insert into storage.buckets …`) с условием «если такой `id` уже есть — обновить настройки, а не упасть на дубликате». Используется в `20261025140000_portfolio_admin.sql` при создании бакета `portfolio-images` — миграцию можно безопасно прогнать повторно (например, если она упала на середине в прошлый раз), и она не продублирует бакет и не завершится ошибкой. |
| GHSA и критичность находки `npm audit` | GHSA (GitHub Security Advisory) — карточка конкретной уязвимости с диапазоном затронутых версий. Один и тот же пакет может сменить объявленную критичность между прогонами audit не из-за изменений в коде проекта, а потому что GitHub пересчитал итоговую степень риска для всего набора находок пакета (на прошлой неделе `next` числился как три «high», сейчас — как один «critical» с более широким диапазоном версий) — список советов обновляется постоянно, независимо от того, трогали мы зависимость или нет. |
| Фронт и бэк одной проверки (`portfolio-input.ts`) | Приём, когда один и тот же модуль без серверных импортов зовут и браузер (форма — чтобы показать отказ до загрузки картинок), и сервер (обработчик — чтобы по-настоящему защититься, раз браузеру верить нельзя). Тот же принцип уже стоял за `checkMapSubmission` у карт; `checkProjectInput` в этом периоде — его копия для портфолио, не новое изобретение. |
| `object-cover` vs сохранение пропорции кадра | `object-cover` обрезает картинку, чтобы заполнить контейнер любой формы — удобно, но срезает края, если пропорция контейнера не совпадает с пропорцией исходника. Фото на `/support` этого периода задано без него (`width`/`height` равны реальным пропорциям файла, `h-auto w-full`) именно потому, что кадрирование скриншота постройки потеряло бы часть того, что должно быть видно, — то же решение, что уже принято для карточки товара в магазине 28.08. |
