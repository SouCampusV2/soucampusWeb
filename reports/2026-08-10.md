- Серверные функции переехали из Вашингтона во Франкфурт (`vercel.json`, `regions: ["fra1"]`) — рядом с базой Supabase; раньше каждый поход в базу с личного кабинета летел через Атлантику, а таких походов на одну загрузку страницы кабинета было несколько подряд.
- Разворот фото на весь экран (был только в модерации) стал общим компонентом `Lightbox.tsx` и появился в магазине и портфолио — покупателю теперь так же видно детали скриншота, как модератору.
- Пять самодельных ссылок «назад» и ~39 текстовых оранжевых ссылок в разных начертаниях сведены к `BackLink`/`INLINE_LINK`.

**9 августа — самый большой заход периода**
- **Заявки на статус креатора.** До сих пор загружать карту мог любой зарегистрированный аккаунт — единственным фильтром была модерация каждой карты отдельно. Теперь: форма заявки на `/resources` (у некреатора вместо списка карт), очередь на `/admin/applications`, решение с причиной отказа, автоматическая выдача `profiles.is_creator` при одобрении, гейт на `/creator/upload` (неодобренного не пускают дальше `/resources`). Флаг `is_creator`, заведённый ещё 24 июля, наконец получил применение.
- **Полный каталог `/admin/products`.** Раньше одобренная карта пропадала из поля зрения админки навсегда. Теперь — список всех карт с поиском (включая по автору), фильтрами по статусу, снятием с витрины с обязательной причиной, мягким удалением (файл и доступ покупателя не трогаются), журналом действий `moderation_log`.
- **`/admin` перестал быть 404.** Сводка: выручка/заказы/средний чек/покупатели за 30 дней, график продаж по дням (свой SVG, без библиотеки — обоснование прямо в `SalesChart.tsx`), топ карт и топ авторов.
- **Дублирующий `getUser()` устранён.** Новый `getCurrentUser()` проверяет подпись токена локально (`getClaims()`), без похода в Supabase — там, где нужна именно скорость, а не мгновенный учёт отзыва токена (для админки, где это важнее, `getUser()` осознанно оставлен, с объяснением прямо в коде).
- **Tiptap (~668 КБ) стал ленивым.** Вынесен в отдельный `RichTextEditor.tsx`, обе формы карты грузят его через `dynamic()` — остальная форма (название, цена, файл) больше не ждёт редактор.
- Заодно почищен баг качества фото на странице товара: `sizes` в `ProductGallery` был занижен (640px) при реальной ширине блока около 1100px на широких экранах — картинка растягивалась и мылила.

## Термины и технологии

| Термин | Объяснение |
|---|---|
| `ERR_REQUIRE_ESM` / CommonJS vs ESM | Два способа, которыми JS-код может подключать другие файлы: старый `require()` (CommonJS) и новый `import` (ESM-модули). Node не может вызвать `require()` на файле, который объявил себя чисто ESM-модулем — получится ровно эта ошибка. Именно так упал `isomorphic-dompurify` на Vercel: внутри его цепочки зависимостей (`jsdom` → `html-encoding-sniffer`) один пакет обновился до чистого ESM, а вызывающий код по-прежнему звал его через `require()`. Решение было не «магический флаг», а замена всей цепочки на `sanitize-html`, у которой этой зависимости просто нет (`src/lib/sanitize.ts`). |
| ISR (Incremental Static Regeneration) и `revalidatePath` | Страницы товаров у нас статические, но пересобираются по таймеру («раз в 60 секунд» — `revalidate = 60`) или по прямой команде. В этом периоде ISR всплыла дважды: как жертва (перегенерация страницы товара падала по той же ошибке `jsdom`, и правки описаний тихо не долетали до прода) и как инструмент починки (`revalidatePath("/shop")` в `src/app/api/admin/catalog/route.ts:128` — команда «пересобери эту страницу прямо сейчас», а не жди минуту, нужная для срочного снятия карты с продажи). |
| JWT-клеймы и `getClaims()` vs `getUser()` | Токен входа (JWT) — это подписанный пакет данных о пользователе, который можно проверить двумя способами. `getUser()` спрашивает сервер Supabase «этот токен ещё действителен?» — идёт в сеть, но узнаёт про отзыв доступа сразу. `getClaims()` (новый `src/lib/current-user.ts`) проверяет математическую подпись токена локально, через WebCrypto, без сети — быстрее, но не узнает, если токен отозвали до истечения срока. Проект использует оба осознанно: `getClaims()` для личного кабинета (скорость важнее), `getUser()` — для админки (`src/lib/admin.ts`), где нужно видеть отзыв доступа немедленно. |
| `cache()` (React) | Функция из React, которая делает так, что несколько вызовов одной и той же асинхронной функции **в пределах одного рендера страницы** превращаются в один реальный запрос — остальные получают уже готовый результат. `getCurrentUser` в `current-user.ts` обёрнута в `cache()` именно для этого: если и страница, и вложенный компонент спросят «кто пользователь», сеть/крипто-проверка отработает один раз, а не дважды. Между разными людьми/запросами кэш не расшаривается. |
| Регион серверных функций (Vercel) | Serverless-функции (наш Next.js backend) выполняются в дата-центре, который Vercel выбирает сам — по умолчанию не обязательно рядом с базой данных. `vercel.json` с `"regions": ["fra1"]` закрепляет Франкфурт — тот же регион, где живёт проект Supabase. Без этого каждый SQL-запрос летел через полмира (Вашингтон → Франкфурт и обратно), и это складывалось: на одну загрузку страницы личного кабинета таких походов было несколько подряд. |
| Мягкое удаление (`deleted_at`) | Вместо реального `DELETE` строки в базе ставится метка времени в колонку `deleted_at` — сама строка остаётся. `products.deleted_at` (миграция `20260809120000`) реализует ровно то, что и требовалось: убрать карту с витрины и из списка автора, но оставить файл доступным тем, кто уже заплатил — реальное удаление стёрло бы и это. Наличие метки времени, а не простого `true/false`, вдобавок даёт бесплатный журнал «когда это случилось». |
| Частичный уникальный индекс (`unique index ... where`) | Обычный уникальный индекс запрещает повтор значения во всей таблице. Частичный действует только на подмножество строк, отобранное условием `where`. `creator_applications_one_open` (`create unique index ... where status = 'pending'`) не запрещает человеку подавать заявку много раз за жизнь (отклонили — исправился — подал снова) — запрещает только иметь **две заявки одновременно в очереди**, что и было целью. |
| Открытый редирект (open redirect) и `safeNextPath()` | Уязвимость, при которой параметр вроде `?next=` после входа в аккаунт уводит человека на чужой сайт, а не туда, куда он ожидал — например, `?next=//evil.com` выглядит как «свой» относительный путь, но браузер читает двойной слэш как чужой хост. `safeNextPath()` (`src/lib/site.ts`) отсекает и абсолютные адреса, и такие протокол-относительные пути, разрешая только настоящие внутренние ссылки — раньше эта же проверка была вручную скопирована в двух местах и рисковала разойтись. |
| `next/image` и атрибут `sizes` | `sizes` — это обещание браузеру заранее, какой шириной на экране будет картинка; по нему браузер выбирает подходящий по размеру файл из набора (`srcset`), ещё до того, как страница сверстается. Если обещание неверное — как было в `ProductGallery.tsx`, где стояло `640px` при реальной ширине блока около 1100px на широких мониторах, — браузер честно скачивает мелкий файл и его же растягивает, отсюда заметное «мыло» на скриншотах карт. |
| Ленивая загрузка (`next/dynamic`) | Способ сказать сборщику «не клади код этого компонента в общий файл страницы — подгрузи отдельным файлом, когда он реально понадобится в браузере». Применено к `RichTextEditor.tsx`: Tiptap с ProseMirror весит около 668 КБ, и раньше это скачивалось и выполнялось ещё до того, как форма «Add a map» вообще становилась видна пользователю — теперь остальная форма (название, цена, файл) оживает сразу, а редактор подгружается параллельно. |
| SVG-график без библиотеки | `SalesChart.tsx` рисует столбчатый график продаж вручную, обычными SVG-тегами (`<rect>`, `<text>`), без сторонней библиотеки визуализации. Осознанное решение (комментарий в файле): тридцать столбиков — это десяток строк разметки, а любая charting-библиотека добавила бы сотни килобайт в бандл ради того же результата. Такой подход оправдан только для простых, разовых графиков — как только понадобится что-то интерактивнее (зум, множество рядов), решение стоит пересмотреть. |
