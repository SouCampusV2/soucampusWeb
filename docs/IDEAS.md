## Подписка на постройки (Patreon-модель внутри магазина)

Помимо разовых заказов карт — модель подписки в духе Patreon (рассмотреть в Этапе 4):
- несколько платных тарифов (черновик — `PricingSection.tsx` на главной, UI уже сделан как драфт);
- подписчики получают доступ к библиотеке готовых построек, которые автор выкладывает регулярно;
- полученные по подписке постройки закрепляются в личном профиле пользователя (нужен профиль/аккаунт — завязано на Supabase Auth, Этап 4);
- более высокие тарифы — доп. права (например, коммерческая лицензия на использование построек).

Статус: только идея + готовый UI-черновик секции на главной. Логика подписок, оплата, привязка построек к профилю не реализованы — планировать при подходе к Этапу 4.

## Аналитика/трекинг посетителей (детальнее)

Отслеживание посещаемости и поведения (сколько заходит, какие страницы смотрят, что кликают).
- **Сделано:** Vercel Analytics (`@vercel/analytics`, `<Analytics />` в `src/app/layout.tsx`) — посещения, источники трафика, устройства. Видно только после деплоя (дашборд Vercel → Analytics), локально в dev ничего не собирает. Бесплатный лимит ~2500 событий/мес; после лимита сбор на месяц останавливается, сайт работает нормально.
- **Следующий шаг (позже, ориентир — перед/во время Этапа 4, когда есть реальные посетители):** детальный трекинг поведения — клики, тепловые карты, записи сессий, воронки покупки. Рассматривать **PostHog** (из коробки heatmaps и session replay) как продвинутую альтернативу/дополнение — особенно ценен на этапе магазина (сценарий «каталог → товар → покупка»). Cookie-consent по возможности не усложнять, выбирать privacy-friendly решения (обычно баннер не требуется).

## Рассылка (newsletter) через n8n + Claude

Идея владельца (2026-07-24): автоматическая рассылка подписчикам. Схема — n8n как «клей»: триггер (новая опубликованная постройка / расписание) → взять подписчиков из Supabase → сгенерировать текст письма (черновик может писать Claude) → отправить через email-API. Важно: массовая рассылка ≠ транзакционные письма — нужны отписка (unsubscribe), согласие на рассылку, забота о доставляемости; для bulk лучше специализированный ESP (Resend Broadcasts / Buttondown / Listmonk / Mailchimp), а n8n + Claude — оркестрация и копирайтинг. Не начато; вернуться после Auth и профилей (нужен список подписчиков с согласием). Транзакционная почта (не рассылка) — см. `SHOP.md` → «Почта».

## Своя админка (подэтап 4E) — кастомный интерфейс сборки товара

Не просто форма с текстовыми полями, а: теги, богатый WYSIWYG-редактор описания (в духе Notion/Tiptap, не голый textarea), поле под разные ссылки, загрузка файла карты прямо там же (сразу в приватный бакет `product-files`, без похода в Table Editor/Storage руками). Ждёт подэтапа E; до него — Table Editor.
