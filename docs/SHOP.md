## Что это такое

Не просто «магазин владельца», а **маркетплейс построек** в духе PlanetMinecraft: несколько креаторов публикуют постройки, покупатели их приобретают. На старте единственный креатор — владелец; система с самого начала проектируется под нескольких (как решение по подписке — заложить в схему, но не строить полный онбординг сразу).

## Изменённые решения (перекрывают прежний план)

- 🟢 **Покупка только с аккаунтом.** Прежнее «гостевой чекаут остаётся» отменено — чекаут требует логина. Причина: почти всё (история покупок, доступ к файлам из профиля, просмотры по аккаунту, оценки, креаторы) завязано на наличие аккаунта. **Сделано.**
- 🔴 **Счётчик просмотров на портфолио убираем из публичного показа.** `ViewCount.tsx`/`SiteViews.tsx` на `/portfolio` снимаются — эту статистику владелец смотрит для себя (в админке/аналитике). На постройках магазина будет свой счётчик — **просмотры по аккаунту** (см. ниже), это другая механика. **Решение принято 2026-07-24, до кода не дошло: оба компонента на месте.**

## Витрина (главная магазина)

Ряды-категории (карусели), как на скриншоте-референсе:
- 🟢 **Most popular** — по числу покупок/рейтингу.
- 🟢 **Recently added** — по дате публикации.
- 🟢 **Free** — постройки с ценой 0. (Плюс появился незапланированный ряд **Top rated**.)
- 🔴 **Top creators** — не постройки, а карточки креаторов (по продажам/рейтингу). Не построен.

### Карточка постройки (структура — как референс, стиль/цвета — наши, см. `DESIGN.md`)

- 🟡 превью-картинка — есть, со стрелками листания скринов; **badge версии** («1.12+», «Axiom available») 🔴 нет, версии как поля не существует;
- 🟢 бейдж цены в углу картинки («€17.90» / «Free»);
- 🟢 заголовок;
- 🟢 имя креатора (акцентным цветом, кликабельно на профиль креатора);
- 🟢 короткое описание в одну-две строки;
- 🟢 звёзды рейтинга + число оценок (с половинками с 2026-08-11);
- 🟢 число покупок.

🔴 Карточка креатора («Top creators»): аватар, ник, суммарный рейтинг/фидбеки, число построек/продаж — не сделана.

## Страница постройки

- 🔴 информация о версиях Minecraft — **отдельным полем**, а не текстом в описании (иначе по ним нельзя фильтровать);
- 🔴 кнопки-ссылки (превью-видео, Discord креатора, доп. материалы);

- 🟡 рейтинг и число покупок — 🟢; **просмотры по аккаунту** — 🔴 не сделаны;
- 🟡 отзывы на постройку: оценка (1-5 с половинками) — 🟢, **текстовый отзыв** — 🔴 (запрошен владельцем 2026-08-19, разобран в [`IDEAS.md`](IDEAS.md#-текстовые-отзывы-и-комментарии-под-картой-2026-08-19): что решить до кода, почему не раньше живых платежей).

## Профиль пользователя

**🟢 Базовый — сделано** (кабинет разъехался на три страницы 2026-07-30):
- `/settings` — имя, фамилия, ник, email, аватар, био, смена пароля;
- `/purchases` — история покупок + скачивание файлов по signed URL из приватного бакета `product-files`;
- `/resources` — свои карты со статусами;
- `/notifications` — уведомления (приходят сами через Realtime с 2026-08-15).

**🟢 Аватарка и редактирование профиля** (запрошено 2026-07-24) — сделано: загрузка в бакет `avatars`, правка ника/имени/фамилии/аватара/био.

**На будущее:**
- 🔴 **вход через Google (OAuth)** — второй способ входа рядом с email+password (решено 2026-07-24). Требует OAuth-приложение Google + redirect URLs; схема уже готова («пароль если есть» — у OAuth-аккаунтов пароля нет). Решено делать не раньше, чем появятся посторонние пользователи, и вместе с выбором ника при первом входе + слиянием аккаунтов на один email.
- 🔴 подключение Discord (OAuth-связь) — поле `discord` в `profiles` есть, самой связи нет;
- 🟢 **кнопка «стать креатором»** — сделана иначе, чем задумывалось: не кнопка, а **заявка** (`/creator/upload` закрыт флагом `is_creator`, заявки разбираются в `/admin/applications`, статус можно отозвать);
- 🔴 у креаторов — фидбеки (отзывы на самого креатора, отдельно от отзывов на постройки).

## Данные (эскиз, детально — в `STRUCTURE.md` при реализации)

Опорные сущности (проектировать под мультикреатора и подписку сразу). Актуальная схема — в `supabase/migrations/` и [`STRUCTURE.md`](STRUCTURE.md) §5.2:

- 🟢 `profiles` — расширение `auth.users`: `first_name`, `last_name`, `display_name`, `avatar_url`, `bio`, `is_verified`, `is_creator`, `is_admin`, `discord`. Публичное чтение — через представление `public_profiles`.
- 🟢 `products` — `creator_id → profiles`, цена целыми центами, `category`, `file_path`, **`state`** (одна колонка состояния вместо четырёх флагов, миграция `20260815130000`).
- 🟢 `orders`/`order_items` — связаны с аккаунтом (`user_id`), гостевые заказы подтягиваются по email.
- 🟡 `product_ratings` — оценка 1-5 с половинками есть; **текстового отзыва на постройку нет** (в плане это был `product_reviews`). ⚠️ Когда дойдёт: класть рядом с `product_ratings`, а не поверх — две таблицы про одно событие разъедутся. Разбор — [`IDEAS.md`](IDEAS.md#-текстовые-отзывы-и-комментарии-под-картой-2026-08-19).
- 🔴 `creator_reviews` — фидбек на креатора: не заведён.
- 🔴 `product_views` — просмотр постройки по аккаунту: не заведён.
- 🟢 Сверх плана: `notifications` (+ Realtime), `creator_applications`, `moderation_log`, `product_images`.

Рейтинг/число покупок/просмотров — производные: считать через SQL-представления/агрегаты, а не хранить руками (тот же принцип, что у нынешнего счётчика посетителей).

## Почта / письма (инфраструктура)

Две разные вещи, не путать:
- 🟢 **Ящик для людей** — `support@soucampus.online` заведён в Hostinger (2026-07-24).
- 🟢 **Письма Supabase Auth** (подтверждение регистрации, сброс пароля) — идут через Hostinger SMTP с нашего домена, шаблон сброса вставлен (закрыто к 2026-08-08).
- 🔴 **Транзакционные письма из приложения** (ссылка на скачивание после покупки, подтверждение заказа, письмо владельцу о новой заявке на карту) — **не написано ни одного**: в коде нет ни Resend, ни nodemailer. Рекомендация прежняя — **Resend** (дружелюбен к Next.js, щедрый бесплатный тариф), верификация домена через DKIM/SPF/DMARC в DNS Hostinger, From вида `orders@`/`noreply@`. Пока роль «сообщить пользователю» целиком несут внутренние уведомления (`/notifications`).
- 🟢 **Чеки об оплате** отдаёт сам **Stripe** — отдельно слать не нужно.

## Разделение ресурсов портфолио ↔ магазин (2026-07-24)

Инстинкт владельца: магазинная логика в навбаре (cart-контекст, иконки) не должна грузиться на портфолио. Верно по принципу, но **не приоритет сейчас** — навбар это пара КБ JS, реальная тяжесть портфолио — картинки 5-14 МБ (см. `CLAUDE.md` open task «Оптимизация картинок»). План: (1) сначала картинки; (2) разделение навбара на `PortfolioNavbar`/`ShopNavbar` (или `next/dynamic` на магазинную ветку) сделать вместе с витриной-маркетплейсом; (3) финал — магазин на отдельном поддомене `shop.soucampus.online` = полностью разные бандлы. Не микрооптимизировать навбар отдельно.

🔴 **Переход на поддомен `shop.soucampus.online` — ОБЯЗАТЕЛЬНЫЙ, не опциональный (решено 2026-07-24), но НЕ сделан.** У магазина будет СВОЙ отдельный навбар (`ShopNavbar`), а не режим общего навбара, как сейчас. Текущий «режим магазина» внутри общего `Navbar.tsx` — временное решение на период разработки; маркетплейс по-прежнему живёт в `(site)/marketplace`. **Учесть при возврате к вопросу:** имя поддомена теперь спорно — раздел называется Marketplace, а не Shop, и `/shop` уже отдан под постоянный 308-редирект.

## Порядок реализации (подэтапы)

Зависимости диктуют порядок — почти всё висит на аккаунтах, поэтому auth первым.

1. 🟢 **Auth (фундамент).** Supabase Auth: регистрация/вход email+password, сессия в Next.js (`proxy.ts` + серверные хелперы), защищённые маршруты, гейт на чекаут, сброс пароля. *(Google OAuth и Discord из этого пункта — 🔴, отложены сознательно.)*
2. 🟢 **Профиль (базовый).** `/settings`: имя/фамилия/ник/email/аватар/био, смена пароля. Таблица `profiles` + триггер создания при регистрации.
3. 🟢 **Покупки в профиле.** `/purchases`: история заказов + скачивание файлов, гостевые заказы подтягиваются по email.
4. 🟡 **Витрина-маркетплейс.** Ряды Most popular / Recently added / Top rated / Free, карточки в нашем стиле, восемь категорий фильтром, поиск по названию, описаниям и имени автора. **Ряд «Top creators» — 🔴 не сделан.**
5. 🟡 **Оценки и просмотры построек.** Оценки (1-5 с половинками, только у купившего) — 🟢. **Текстовые отзывы на постройку и просмотры по аккаунту (`product_views`) — 🔴.**
6. 🔴 **Убрать счётчики просмотров с портфолио** (публичный показ). Решено 2026-07-24, **не выполнено**: `ViewCount`/`SiteViews` по-прежнему стоят на `/portfolio` и `/portfolio/[slug]`.
7. 🟡 **Креаторский UI загрузки постройки** — **сделано 2026-07-30.** `/creator/upload`: WYSIWYG-описание на Tiptap с картинками и таблицами, галерея с перетаскиванием и выбором обложки, категория, цена, загрузка файла в `product-files`. Плюс то, чего в плане не было, но без чего оно не работает: очередь модерации `/admin/moderation`, отказ чек-листом с проверкой при повторной отправке, правка своих карт `/resources/[slug]/edit`. **🔴 Хвост: версии Minecraft отдельным полем и внешние ссылки (превью-видео, Discord автора) так и не сделаны.**
8. 🟡 **Креаторы (полноценно).** Профиль креатора `/creator/[username]` — 🟢; «стать креатором» по заявке с очередью в админке и отзывом статуса — 🟢. **Фидбеки на креатора и «Top creators» — 🔴.**
9. 🔴 **Подписка (Patreon), будущее.** См. `IDEAS.md`. Не начата.
