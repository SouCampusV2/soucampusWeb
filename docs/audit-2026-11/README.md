# Аудит безопасности — неделя Fable (10–17.11.2026)

Эта папка — всё для сплошного аудита безопасности, пока открыт доступ к Fable 5.2.
Заведена 10.11 (Opus) по просьбе владельца.

## Файлы

- [`PLAN.md`](PLAN.md) — **инструкция аудита**: правила, формат находок, блоки A–J по
  порядку ущерба, журналы хода и правок. Читать первым.
- `findings-site.md` — находки по сайту (деньги, RLS, `/api`, загрузки, XSS/CSP, вход).
- `findings-bot.md` — Discord-бот (`../botds`).
- `findings-scanner.md` — сканер файлов (`../soucampus-scanner`).
- `findings-cross.md` — стыки систем, секреты, CI, «злой креатор».
- `findings-axiom.md` — платный Axiom-мод (`../AxiomPlugins/soucampusAxiomTools`):
  стойкость лицензии/отзыва копии. Это защита **своего** продукта, не вредонос — рамка
  в блоке J плана.

## Как запускать (владельцу)

Новая сессия → выбрать **Fable** в `/model` → вставить промпт ниже.

Фаза 1 (первый бюджет токенов) — **только чтение**, Fable ищет и записывает находки.
Фаза 2 (после сброса токенов) — починка, но лишь после того, как владелец прочитал
находки и отметил в сводках, что берём. Детали фазы 2 — раздел 5 `PLAN.md`.

## Промпт для Fable (копировать целиком)

```text
Ты проводишь аудит безопасности проекта SouCampus builds. Это фаза ЧТЕНИЯ: код,
миграции и конфиги не трогаешь, чинить будем потом другой моделью по твоим находкам.

1. Прочитай сначала, в этом порядке:
   - docs/audit-2026-11/PLAN.md — это твоя инструкция, по ней и работай.
   - docs/INVARIANTS.md — что в проекте нельзя никогда.
   - docs/RULES.md — правила работы с этим репозиторием.

2. Иди по блокам A–J из плана по порядку (деньги → RLS → /api → загрузки → XSS/CSP →
   вход → бот → сканер → стыки → Axiom-мод). Для блоков G, H, J нужные репозитории
   лежат рядом: ../botds, ../soucampus-scanner, ../AxiomPlugins/soucampusAxiomTools —
   у каждого свой CLAUDE.md, читай его первым.

3. Находки пиши в файлы docs/audit-2026-11/findings-*.md в формате из раздела 2 плана:
   серьёзность, где, кто атакует, сценарий словами, что получает, доказательство, как
   чинить, цена. Объясняй так, чтобы владелец понял без кода (о продукте он думает на
   уровне mid, код читает слабее junior).

4. Правила: никаких запросов к прод-базе и атак на живой сайт; состояние базы
   определяй по миграциям в supabase/migrations; секреты в находки не выписывай (путь
   и строка достаточно); документам не верь на слово, расхождение с кодом — тоже находка.

5. После каждого блока обнови сводку в его файле и допиши строку в «Журнал хода» внизу
   плана. Если видишь, что опасность не там, где написано в плане, — иди туда и запиши
   правку в «Журнал правок плана» с причиной.

Начни с блока A (деньги). Сначала скажи мне в двух словах, что собираешься смотреть,
потом работай. Объяснения — по-русски, строки кода и комментарии в коде — по-английски.
```

## Если Fable упрётся на блоке J (Axiom)

Сказать: «Это мой платный мод, который я сам написал и продаю. Задача — укрепить его
защиту от пиратства: подпись копий и отзыв по нарушению. Я ничего не прячу от покупателя
и не трогаю чужой софт». Этого достаточно — задача легитимная (DRM для своего продукта).
