# Инварианты — что нельзя никогда

Короткий список «нарушишь — молча откроешь дыру или потеряешь чужие деньги».
Читать **первым**, до любой правки записи в базу, прав, миграций, загрузок и
оплаты. Каждое правило стоило нам дня или дыры на проде; полный разбор — по
ссылке в конце строки. Заведён 03.11 (задача 4 из `IDEAS.md` → «Порядок в
работе с Claude»): раньше эти правила были разбросаны по 1800 строкам
`CLAUDE.md`.

Правило здесь — только если его нарушение **не видно** (ошибок ноль, сайт
выглядит исправным). Всё, что ловит сборка или тест, сюда не попадает.

## Запись в базу

1. **Из браузера в базу не пишет ничего**, кроме восьми колонок `profiles`
   (`username`, `first_name`, `last_name`, `bio`, `name_color`, `avatar_url`,
   `banner_url`, `links`) и форм Supabase Auth. Список — это `grant update`
   в миграциях; сверить с базой — `checks.sql`, раздел 7. Новая запись — только через свой обработчик
   `/api/*`. Одна строка `.insert(` в компоненте возвращает 14-й путь мимо
   шлюза. → `ARCHITECTURE.md` § 5.4
2. **Служебный ключ выключает триггеры**: машину состояний карты, лимиты
   комментариев и реакций, `has_purchased()` (отвечает «нет» всегда).
   Обработчик под служебным ключом обязан повторить их сам; при переезде пути
   смотреть всё в базе, что спрашивает про роль. → CHANGELOG 13.09, 21.09
3. **Запрет ставится там, где стоит разрешение.** Скрытая кнопка, спрятанная
   форма, заблокированное поле не защищают ничего. → CHANGELOG 20–21.08
4. **Поле `profiles`, которое что-то разрешает или удостоверяет**
   (`is_admin`, `is_creator`, `is_verified`, `is_founder`, паузы…), получает
   свой триггер **той же миграцией**, что и колонку. Новая колонка `profiles`
   закрыта правами по умолчанию: попала в форму настроек — выдай `grant` той
   же миграцией. → CHANGELOG 21.08, 15.09

## Права Postgres

5. **Новая функция в `public`:** `revoke all ... from public;` **и**
   `... from anon, authenticated;`. `execute` роли PUBLIC выдаётся сам, и
   `revoke from authenticated` его не снимает. → `RULES.md` → «Проверки руками»
6. **Новое представление в `public`:** сначала `revoke all ... from public,
   anon, authenticated`, потом `grant select`. `grant` права только добавляет,
   а Supabase по умолчанию выдаёт всё — 22.09 аноним так писал в `profiles`.
7. **Новая таблица — RLS всегда**, даже в `ops`, даже если «снаружи её не
   видно». Защита в чужих настройках (Exposed schemas) — не защита.
8. **Отказ RLS на `update`/`delete` — ноль строк, а не ошибка.** Проверять
   состояние строки, а не наличие ошибки.
9. **Конечное состояние называть свойством, а не списком имён.** `drop policy
   if exists "имя"` молча ничего не делает, если политику назвали иначе
   (руками в дашборде). Снимать «все, кроме чтения», проверять запросом к
   `pg_policies`. → CHANGELOG 21.09
10. **Отказ по двум причинам не доказывает ни одну.** Проверка запрета обязана
    падать только из-за того запрета, который проверяет (`check:guards`).

## Карта и её состояние

11. **Состояние карты — только `state`.** Видимость на витрине =
    `state = 'live' and creator_active`; формула повторяется в политике,
    `getAllProducts` и сводке каталога — дословно одинаково.
12. **Переходы знает база** (`guard_product_state`), новая карта начинается с
    `pending` (`guard_product_insert`). Новый переход — правка триггера, а не
    проверка в обработчике.
13. **Файл удалённой карты не удаляется** — покупатели скачивают оплаченное.
    Уборка «через 30 дней» отменена 10.09. Удаление мягкое у обеих сторон.

## Деньги

14. **`/api/stripe/webhook` проверяет подпись и не лимитируется никогда** —
    Stripe повторяет при отказе, лимит значит «деньги взяты, карта не выдана».
15. **Бесплатная карта — та же дверь `/api/checkout`**, ветку выбирает сервер
    по цене из базы. Повторное получение запрещает уникальный ключ
    `free:<карта>:<человек>` в базе, а не проверка в коде.
16. **`getPaidOrder` принимает только `cs_`**, и проверка стоит до создания
    клиента. Ключ бесплатного заказа угадываем.

## Загрузки

17. **Клиент не называет, куда писать.** Токен — только на `pending-…`, на
    постоянный путь кладёт `confirm`; ссылка на `pending-` нигде не
    принимается. → CHANGELOG 11.09, 01.11
18. **Картинка — только наша** (`isOwnImageUrl`): обложка, описание, аватар,
    баннер. Свой домен Storage или третий проект — дописать туда отдельной
    миграцией, иначе картинки молча пропадут.
19. **Пока `soucampus-scanner` не запущен, каждую чужую карту владелец
    смотрит в очереди сам** — креаторство открыто 27.10 до сканера.

## Миграции и секреты

20. **Добавляющая миграция — до деплоя, удаляющая — после.** Срок
    проверяется по **каждому разделу** файла, а не по заголовку. Сначала
    preview, потом прод; последней строкой — запись в
    `ops.applied_migrations`. → `RULES.md` → «Миграции»
21. **Состояние прода — запросом, а не памятью** и не документом.
22. **`SUPABASE_SERVICE_ROLE_KEY` — только в серверном коде.** Клиентскому
    модулю нужна форма данных — выносить в `*-shape.ts`.
23. **Страница, собираемая заранее, не падает без служебного ключа** — в CI
    его нет. Перед пушем `SUPABASE_SERVICE_ROLE_KEY= npm run build`.

## Интерфейс

24. **На тач-экране `hover` не наступает никогда.** Меню и действия только
    на `group-hover` на телефоне не существуют. Зоны нажатия — по
    `pointer-coarse:`, а не по ширине. → `DESIGN.md`
25. **Ссылка из данных — через `safeHref`** (только внутрь сайта).
