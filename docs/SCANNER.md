# Сканер файлов — отдельный сервис на Java

План от 2026-10-20. Приоритет №1 из `CLAUDE.md` («проверка загружаемых
файлов на вредоносность»), заодно первый настоящий проект владельца на Java
и первый Docker в проекте (Этап 5 из `docs/ROADMAP.md`).

**Код сервиса пишет владелец.** Моя часть — объяснять до кода, разбирать
результат и править сторону `FirstTry` (вызов из `confirm`). Правило
обучения из `CLAUDE.md` → «Постоянная колея».

### Решение о разморозке креаторства (20.10)

Владелец решил вернуть возможность стать автором. Звать авторов **пока не
собирается**, так что риска сейчас нет. Это повод достроить функционал и
сделать проверку файлов. Решения владельца по вопросам из `docs/IDEAS.md` →
«Что решить до кода»:

| Вопрос | Решение 20.10 |
|---|---|
| Кто продавец | **Площадка (владелец).** Решено не словами, а выплатами: деньги приходят на Stripe владельца, авторам он переводит руками. Значит, фактически продавец он, что бы ни было написано в условиях. ⚠️ Следствие: в налоговый оборот идёт **вся** цена чужой карты, а не только доля площадки. Когда чужих продаж станет заметно — бухгалтер (`BUSINESS.md` § 11) |
| Комиссия | Stripe платит автор, площадке **2–3%**. ⚠️ Stripe берёт ~3.25% + €0.25 с карты не из ЕС. На карте за €3 автор отдаёт Stripe ~12%. Возможно, нужна минимальная цена чужой карты |
| Выплаты | Автор запрашивает **раз в неделю**, владелец переводит **руками**. Stripe Connect — потом. Учёт балансов — кандидат для `souc-ledger` (`docs/IDEAS.md`) |
| Карту сняли за нарушение после продажи | 🔴 **Не решено.** Вопрос не в том, отдавать ли деньги автору (да), а в том, кто платит возврат покупателю. Решить до первой чужой продажи, записать в договор с автором |
| Возраст | **Только 18+.** Минимум — галочка «мне есть 18» в заявке, сохранённая в базе с датой |

## 2. Что проверяется сейчас и где дыры

Шлюз загрузки (11.09) режет путь на два шага: `sign` выдаёт токен на путь,
который построил сервер, `confirm` смотрит, что легло. Для файла карты это
`src/app/api/creator/upload/route.ts`, для картинок —
`src/app/api/creator/image/route.ts`. Сами проверки — чистые функции в
`src/lib/upload-limits.ts`.

| | Что проверяется | Чего нет |
|---|---|---|
| Файл карты | размер, расширение, **первые 12 байт** (zip / gzip / NBT) | содержимое zip: внутри может лежать что угодно, включая `.exe`. Zip-бомбы. Антивирус |
| Картинки | размер, расширение, **первые 12 байт** (PNG / JPEG / GIF / WebP) | всё, что после заголовка |

### Картинки — подробнее (найдено 20.10)

- **Полиглот.** Настоящая картинка, в хвост которой дописан скрипт, zip или
  exe. Заголовок честный, проверка 12 байт пройдена.
- **Посетителю витрины это почти не опасно:** `next/image` перекодирует
  картинку в AVIF/WebP, и браузер получает чистые пиксели.
- **Опасен сырой адрес в бакете.** `product-images` публичный, прямую
  ссылку можно раздавать. Тогда это хостинг заразы на нашем Storage.
- ⚠️ **`Content-Type` задаёт загружающий.** `uploadToSignedUrl` в
  `src/lib/upload-client.ts` берёт тип файла из браузера, и `confirm` его
  не сверяет. Можно положить «картинку» с типом `text/html`: PNG-заголовок,
  за ним HTML. **Не проверено, отдаёт ли Supabase такой тип как есть.**
  🟢 Заплатка в `FirstTry` сделана: `confirm` картинок сверяет тип
  объекта со списком из четырёх (`checkImageContentType`), без типа —
  отказ. 🔴 Проверить на preview загрузкой обычной картинки: если
  Storage не отдаёт тип в `info()`, откажет всем.

### Как закрываем

| | Файл карты | Картинка |
|---|---|---|
| Что делает сервис | распаковать zip с лимитами → каждый файл в ClamAV → свои правила (`.exe`, `.jar`, `.bat`, `.dll`, `.ps1`… внутри — отказ) | ClamAV + **перекодировать** (раскрыть в пиксели и собрать заново) |
| Что возвращает | вердикт | вердикт + новые чистые байты, которые кладутся вместо исходных |

**Почему перекодирование.** Антивирус ищет известное. Перекодирование
уничтожает всё, что не пиксели: хвосты, метаданные, EXIF и геолокацию с
телефона. В Java это `ImageIO` (PNG, JPEG, GIF из коробки; для WebP —
плагин TwelveMonkeys).

⚠️ **Это всё ещё не гарантия.** ClamAV ловит известное, а мод с
вредоносным `.jar` внутри, которого ещё нет в базах, пройдёт. Свои правила
по расширениям внутри zip закрывают большую часть этого: в схематике и мире
исполняемым файлам делать нечего.

## 3. Как устроено

```
браузер ──sign──▶ /api/creator/upload (Next, Vercel fra1)
браузер ──файл──▶ Supabase Storage (мимо Vercel: потолок тела 4.5 МБ)
браузер ─confirm▶ /api/creator/upload
                     │  POST https://<сканер>/scan
                     │  { signed URL объекта, kind: map | image }
                     │  + общий секрет в заголовке
                     ▼
              souc-scanner (Java, Docker, VPS)
                     │ скачать по ссылке → распаковать / перекодировать
                     │ → clamd по TCP (соседний контейнер)
                     ◀ { verdict: clean | infected | rejected | error, reason }
                     │
                  clean → принять (картинку — заменить чистыми байтами)
                  иначе → reject(): удалить объект, объяснить человеку
```

### Правила, принятые сразу

- **Сканер недоступен — значит ОТКАЗ, а не пропуск.** Иначе упавший сервис
  молча открывает дверь. То же правило, что в `check:guards`: «не
  проверено» не должно выглядеть как «прошло». Человек видит «проверка
  временно недоступна, попробуйте через минуту».
- **Сервисы общаются по общему секрету** (заголовок, секрет — в `.env` на
  VPS и в переменных Vercel). Сканер торчит в интернет: без секрета любой
  гонял бы через него свои файлы и тратил наш CPU.
- **Сканер сам ничего не пишет в базу и в Storage.** Он только читает по
  одноразовой ссылке и отвечает. Решает и удаляет `confirm`, как сейчас.
  Служебного ключа Supabase на VPS нет и не будет.
- **Синхронно.** Zip на 15 МБ сканируется секунды, у функции Vercel 300 с.
  Очередь не нужна, пока не станет нужна.
- **Лимиты распаковки:** число файлов, суммарный распакованный размер,
  глубина вложенных архивов, коэффициент сжатия. Это защита от zip-бомбы:
  42 КБ, которые распаковываются в петабайты.

### Почему не на Vercel рядом с Next (как FastAPI в TutorWeb)

`clamd` — демон, который держит в памяти базу сигнатур (~1–1.5 ГБ) и
грузит её десятки секунд. Функция Vercel живёт коротко, и каждый холодный
старт грузил бы базу заново. Нужен постоянно работающий процесс, то есть
контейнер на своём сервере.

### Почему не Railway

Бесплатного тарифа в старом виде там, насколько известно на 20.10, нет, а у
пробных и дешёвых планов мало памяти: ClamAV туда не помещается. Условия
Railway не перепроверялись, но по памяти он не подходит в любом случае.

## 4. VPS (Hostinger, сверено по скриншоту панели 20.10)

| | |
|---|---|
| Тариф | Hostinger **KVM 1**, оплачен до **2027-02-10**, автопродление включено |
| Где | Germany — **Frankfurt**. Там же функции Vercel (`fra1`) и Supabase |
| ОС | **Ubuntu 24.04 with n8n** (шаблон Hostinger) |
| CPU | 1 ядро, нагрузка ~1% |
| Память | **4 ГБ**, занято ~18% (~0.7 ГБ, это n8n) |
| Диск | 50 ГБ, занято 8 ГБ |
| Трафик | 4 ТБ в месяц |
| Бэкапы | еженедельные (ежедневные — 139 грн/мес, не нужны) |
| Брандмауэр | 4 правила (не разобраны) |
| Вход | SSH под `root`, по паролю |

Адрес и имя хоста намеренно не записаны: они в панели Hostinger, а этот
файл лежит в репозитории.

### Бюджет памяти

| | |
|---|---|
| n8n | ~0.7 ГБ |
| `clamd` | ~1–1.5 ГБ |
| Java-сервис | ~0.3 ГБ (ограничить `-Xmx256m`) |
| **Итого** | **~2.5 ГБ из 4** |

⚠️ **Ловушка:** при обновлении сигнатур (раз в несколько часов) ClamAV по
умолчанию грузит новую базу **рядом со старой**, и на минуту памяти нужно
вдвое больше. Это уже впритык к 4 ГБ. Лечится так:
- `ConcurrentDatabaseReload no` в настройках `clamd`. На ~30 секунд
  перезагрузки сканер отвечает «недоступен», то есть отказом, и человек
  повторяет загрузку;
- **swap на 2 ГБ** как подушка.

### До того, как ставить туда что-то своё

1. 🔴 **SSH-ключ вместо пароля**, вход по паролю отключить. Через этот
   сервер пойдут файлы магазина.
2. 🔴 **Посмотреть, что запущено** (`docker ps`). Шаблон с n8n почти
   наверняка уже содержит Docker и обратный прокси с HTTPS (у Hostinger
   обычно Traefik). Встраиваться рядом и **не сломать n8n**.
3. 🔴 Разобрать 4 правила брандмауэра. Наружу должен смотреть только
   HTTPS через прокси, порт `clamd` (3310) — никогда.
4. ⚠️ Плитка «Сканер шкідливих програм: Не встановлено» в панели — это
   антивирус Hostinger для самого сервера, к нашему сканеру отношения не
   имеет.
5. Сделать снимок (snapshot) в панели перед первыми правками.
